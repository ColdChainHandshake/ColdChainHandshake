- 2026-10-30. Installed portable Temurin 17 at `D:\cch-tools`. Why: AGP 8.2 needs JDK 17, the machine only has Java 8 and Java 25, and Android Studio is missing, so nothing can be built; a JDK is a build dependency, the same thing Gradle toolchain provisioning would fetch. Rule 5.0.8 limits installs to project dependencies, so this is the one exception and it is reported to the owner. PATH, registry and `~/.gradle` untouched; delete the folder to remove it. Alternatives: stop until the owner installs one (blocks every phase), or use the local Gradle 9.2 dist (AGP 8.2 cannot run on it).

- 2026-10-30. Seed profile: 2 to 8 °C, 5 minutes of heat, 0 minutes of freeze, a reading every 60 s, gap after 3 intervals. A second profile, `test-2-8-freeze-tolerant`, exists only so per-product behaviour can be exercised, and says so in its name. An unknown profile ID gets the strictest rules.
- 2026-10-30. A reading speaks for at most `maxSilenceMs`, and a gap ends an excursion. Why: time inside a gap must count neither as safe nor as hot. Alternative: credit the whole gap to a hot reading, as the old code did, which fabricates a breach during a dropout.
- 2026-10-30. A budget of 0 means any reading past that limit fails. Why: with strict `>` on proven duration, a final or only reading of -3 °C proves 0 ms and would pass.
- 2026-10-30. Excursion evaluation takes `windowStart` and `windowEnd`. Why: without them a late first reading or a logger going quiet before handover can't be seen. `Shipment` gains `journeyStartedAt` for this. It is not the dispatch time, because the wait between Dispatch and Start Journey would otherwise show up as a gap.

- 2026-10-30. Test expectation changed: `networkDropoutDoesNotFabricateBreachDuration` and `networkDropoutDoesNotTriggerFalseBreachOrQuarantine`, a 10-minute gap was a pass, now UNKNOWN (finding 6). Their assertion that gap time isn't counted as hot is unchanged.
